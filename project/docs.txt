
Фаза 1: Discovery (Исследование и проектирование)

• Этап 1.1 (Бизнес-брифинг):
	• Протокол встречи (Minutes of Meeting / MoM) — фиксация договоренностей созвона.
	• Бизнес-бриф / Lean Canvas — концепция бизнеса заказчика на одном листе.
• Этап 1.2 (Исследование):
	• Отчет об анализе конкурентов (Competitor Analysis Report) — разбор фич и механик рынка.
	• Профили персонажей (User Personas profiles) — карточки ключевых типов пользователей.
• Этап 1.3 (UX-проектирование):
	• Карта пути пользователя (User Journey Map / UJM) — Miro/FigJam схема барьеров и шагов.
	• Логические схемы (User Flow Diagrams) — алгоритмы переходов по экранам.
• Этап 1.4 (Функциональные требования):
	• Бэклог продукта (Product Backlog / User Stories) — плоский список всех фич в Jira/Notion.
	• Карта экранов (Sitemap / Screen Map) — иерархическая структура разделов продукта.
• Этап 1.5 (Приоритезация MVP):
	• MVP Scope Document — перечень функций, входящих строго в первую версию.
• Этап 1.6 (Прототипирование):
	• Кликабельный интерактивный прототип — Low-fidelity макеты в Figma (ссылка на проект).
• Этап 1.7 (Техническая архитектура):
	• Техническое задание (ТЗ / PRD — Product Requirement Document) — главный документ для разработки.
	• Схема базы данных (ER-диаграмма) — сущности и связи данных.
	• Спецификация интеграций (API Integration Specs) — методы работы с внешними сервисами.
• Этап 1.8 (Roadmap и Смета):
	• Календарный план-график (Roadmap / Диаграмма Ганта) — сроки спринтов и вехи.
	• Коммерческое предложение (КП) и Смета — финальная калькуляция стоимости.

Фаза 2: Design (Визуальный дизайн)

• Этап 2.1 (UI-концепт):
	• Мудборд (Moodboard) — подборка визуального стиля, шрифтов и референсов.
	• Концепт-дизайн главных экранов — первые цветные варианты интерфейса.
• Этап 2.2 (Отрисовка):
	• Готовые UI-макеты (High-fidelity mockups) — все экраны во всех состояниях в Figma.
• Этап 2.3 (UI-Kit):
	• Дизайн-система / UI-Kit — библиотека компонентов, стилей и токенов.
• Этап 2.4 (Передача):
	• Инструкции по спецификациям дизайна (Hand-off documentation) — описание анимаций и логики элементов для разработчиков.

Фаза 3: Development (Разработка)

• Этап 3.1 (Настройка окружения):
	• Архитектурный манифест (Infrastructure as Code / README в Git) — описание сред (Dev/Stage/Prod) и доступов.
• Этап 3.2 (Backend):
	• Интерактивная документация API (Swagger / Postman Collection) — описание всех эндпоинтов для фронтендеров.
• Этап 3.3 & 3.4 (Frontend & Интеграции):
	• Коммиты и Пулл-реквесты (Pull Requests) — задокументированные изменения в коде.
	• Сборки проекта (Builds) — готовые файлы .apk, .ipa или веб-архивы на стейджинге.

Фаза 4: QA & Testing (Тестирование)

• Этап 4.1 (План тестов):
	• Тест-план (Test Plan) — общая стратегия тестирования.
	• Тест-кейсы (Test Cases / Checklists) — пошаговые сценарии проверок в Qase/TestRail.
• Этап 4.2 & 4.3 (Проверки):
	• Баг-репорты (Bug Reports) — тикеты об ошибках с логами и скриншотами в Jira.
• Этап 4.4 (Регресс):
	• Итоговый отчет о тестировании (QA Release Report / Тест-вытрезвитель) — официальный документ о качестве сборки и готовности к релизу.

🚀 Фаза 5: Deployment & Release (Релиз)

• Этап 5.1 (Публикация):
	• Примечания к релизу (Release Notes) — описание изменений для пользователей в сторах.
	• Чек-лист деплоя (Deployment Checklist) — пошаговый план выкатки на продакшен (для DevOps).
• Этап 5.2 (Аналитика):
	• Карта разметки аналитических событий (Analytics Tagging Plan) — ТЗ для сбора метрик (какие клики куда отправлять).
• Этап 5.3 (Smoke-тест):
	• Протокол валидации продакшена — подтверждение работоспособности основных бизнес-функций на живых серверах.

🔄 Фаза 6: Support & Evolution (Поддержка)

• Этап 6.1 (Мониторинг):
	• SLA (Service Level Agreement) — регламент скорости реагирования на баги разного уровня критичности.
	• Логи инцидентов (Incident Logs) — отчеты о падениях серверов и принятых мерах.
• Этап 6.2 (Анализ):
	• Продуктовые дашборды (Product Analytics Dashboards) — настроенные отчеты в Amplitude/Mixpanel.
	• Бэклог улучшений (Product Backlog V2) — список доработок на основе фидбека рынка.
